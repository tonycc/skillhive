# PRD 评审清单

> 评审时逐项对照。标 🔴 的为阻断项，不通过则不能进入开发。

## 一、背景与目标

- 🔴 是否说清楚了「为什么做」（业务痛点 / 数据依据）？
- 🔴 目标是否可衡量（有明确的指标和预期数值）？
- 是否明确了「不做什么」（范围边界）？

## 二、用户与场景

- 目标用户画像是否具体（角色、规模、使用频次）？
- 🔴 核心使用场景是否覆盖完整（主路径 + 异常路径）？
- 是否考虑了权限差异（不同角色看到/操作的内容）？

## 三、功能描述

- 🔴 每个功能点是否有明确的输入、处理逻辑、输出？
- 🔴 边界条件是否定义（空值、超限、并发、重复提交）？
- 交互流程是否有原型或流程图支撑？
- 文案、报错提示是否给出？

## 四、数据与依赖

- 涉及的数据字段是否有定义（名称、类型、来源）？
- 🔴 外部依赖是否明确（接口、第三方服务、其他团队排期）？
- 数据迁移 / 历史数据兼容是否考虑？

## 五、非功能性需求

- 性能要求（响应时间、并发量）是否量化？
- 安全与合规（敏感数据、权限校验、审计日志）是否涉及？
- 灰度与回滚方案是否说明？

## 六、排期与验收

- 🔴 验收标准是否可测试（每条都能写出用例）？
- 里程碑拆分是否合理，风险项是否标注？
